# 一次短实机验收

先只启用 Release 和所需 Loader，停用旧 C4 控制器。无需先运行诊断包。建议先单人同一场景完成以下检查，记录不符合预期的具体步骤即可。

1. **自动模式与左投右爆**：分别从 DEPLOY 和 DETONATE 开始，拿出 C4、松开双键，确认左键投掷、右键起爆。菜单把模式改为 DETONATE 后退出并松键，再试一次；条件允许时补一次重生/重新拾取后的检查。退出并重新进入游戏，观察菜单模式是否被游戏保存。
2. **反馈与并发**：已有 C4、站立空闲时右键两次，观察是否有原生按压、是否一按一次爆炸；再在投掷刚出手和装填期间右键，确认能迅速引爆。忙碌时本轮不承诺额外按压动画。不要用连续右键测试替代一次明确按下/松开。
3. **切枪窗口**：投掷后按 1 切枪，在“刚开始收起”“主武器快举起”“已经瞄准”分别新按右键，预期不会新提交 C4 引爆；切回后先一直按住右键，预期不补爆，松开再按才恢复。已在切枪前提交的爆炸单独记录，不能当作切枪后新请求。
4. **短弹药账目**：记录初始弹量和补给，完成约 10 次投掷，混合空闲、出手后、装填中引爆和一次取消投掷。核对只有实际投出的 C4 消耗弹药，右键不额外扣弹、没有异常自动投掷。它是短样本，不代替长期证明。
5. **性能**：同一地图、画质和帧率限制下，记录未持 C4 约 30 秒、持 C4 空闲约 30 秒、上述操作期间的帧时间/卡顿。若与 M1.3 比较，使用相同条件和同一测量工具；Release 不内置逐帧计时，不能用它的极少量日志推算运行毫秒数。

反馈可直接写：“步骤 / 实际先后顺序 / 是否投出、按压、爆炸 / 弹量 / 性能观察”。有异常再提供 Release 的启动/故障日志；只有定位具体故障确有需要时才换 Diagnostic，避免重新开启通用采集循环。若卡在模式校正、停止响应或 Aim 未恢复，退出本局停用该包并保留日志。

本轮不要求先做联机验收；主客机、所有姿态和长时间使用仍标为未验证。
