# 1.0.0-rc1 发布说明

依据 Astra《C4快速引爆完整收尾方案 v4》从 M1.3 迭代，交付日用 Release 和独立诊断构建。

| 事项 | 本轮改动 | 验证边界 |
| --- | --- | --- |
| 常驻成本 | Release 去除边界采集、详细阶段计时、慢帧环、弹药诊断、后置目标扫描、持续刷盘；保留 Aim hints 和新鲜身份校验 | 两构建编译及离线回归通过，实际毫秒数待测 |
| 切枪误爆 | 当前布局 bit111 在 before、after、最终提交前否决；取消旧请求、释放自有 Aim，松键后重新接管 | 1152 个历史样本支持有限采用；新包尚未进游戏 |
| 自动模式 | 当前 C4 实例的模式字段，在空闲双键释放时比较、清除 selector 位并回读；不持续写、不写共享模板 | 自有内存真实 Windows API 测试及合成组件校验通过；菜单、重生、拾取和持久化待测 |
| 按压反馈 | F2：严格空闲时只调用原生 start520；忙碌时只调用 owner-batch remote | 原生链关联及互斥路径已离线核验，实际动作和爆炸待测；忙碌路径仍无额外按压动画 |
| 弹药 | 左键投掷、扣弹、装填继续由游戏处理；本包不调用 consume/after/reload | 不等于长期账目已证明，短验收继续核对 |
| 异常 | 请求提交前消费；调用/完成状态不确定不重试、不切换另一条路径；纯日志写失败不补发动作 | 离线覆盖不确定返回、520 未被观察到、切枪/UI 清理 |

原生 setter 和纯表现入口均未得到足够证据：`fn_selector` 是读取器；520 phase0 涉及未知事件调用，不能当作纯动画接口直接调用。因此实现局部实例校正和有条件 F2，未猜测新动画 ID、未补造模式 setter。

尚未完成的真实验证：空闲引爆的原生按压是否符合手感；自动 DEPLOY 在两种初始模式、菜单、重生和拾取下是否稳定；切枪窗口是否完全关闭；Release 的实际开销；短弹药账目及联机行为。当前名称保留 rc1，不宣称已经全部实机通过。

历史十个构建压缩包哈希均保持不变。当前游戏仍部署旧 M1.3，本轮未部署、未启动游戏。具体检查见同目录 `离线验证.json`、`历史与部署只读核验.json`、`实现与验证报告.md`。
